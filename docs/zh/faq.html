常见问题 ​

启动报错：the value for "version" in ~/.dsh/.credentials.yaml must be a string ​

这是 dsh 内核读取凭据配置失败，不是本应用问题。原因通常是 .credentials.yaml 顶层 version 为数字。

修复：编辑 C:\Users\<你>\.dsh\.credentials.yaml（或对应主目录），把首行改为带引号：

yaml
version: "1"

保存后重新启动。内部 payload.version 无需改动。

启动后一直停留在加载转圈，进不去界面 ​

应用通过 dsh 打印的 dsh web: <url> 解析地址。若长时间无 URL：

  • 查看「终端」视图的 dsh 输出是否有报错；
  • 检查所选端口是否被占用（会自动上扫空闲端口）；
  • 确认内核已安装、工作目录存在且可读。

按 F12 控制台没反应 ​

控制台需要先开启开发模式：设置 → 关于 → 打开「开发模式」。默认关闭以避免误开。

为什么卸载 / 升级要“先停止 dsh” ​

Windows 下运行中的 dsh 会锁定内核模块文件，导致替换/删除失败。应用会先停止再操作；若仍有进程占用会检测并提示你先关闭相关进程。

无法连接 / 检查更新失败 ​

  • 检查网络，必要时在设置内把内核镜像源切到 npmmirror 试一次；
  • 应用与内核更新走不同通道（GitHub / npm），若 GitHub 不可达，应用自更新可能失败而内核不受影响。

想同时打开多个实例 ​

默认单实例：重复启动会唤起已有窗口并置前，而不是新开一个。

注意区分「多实例」与「多窗口」：应用支持多窗口——在标签上右键「在新窗口打开」即可开出副窗口（见标签页与多窗口）。这是同一个应用内的多个窗口，不是同时运行多个应用实例。

其它 ​

若以上未解决，请带上「终端」视图的日志与版本号（应用版本、内核版本）反馈给维护者。
